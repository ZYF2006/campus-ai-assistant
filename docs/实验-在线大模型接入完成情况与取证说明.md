## 三、关键代码

### （1）在线模型调用（`apps/server/src/services/llm.ts`）

本工程刻意**不安装 `openai` 依赖**，用原生 `fetch` 发送与 SDK 完全相同的 OpenAI 兼容报文，
这样代码里能直接看到「协议本身」。核心片段：

```ts
export async function chatWithBailian(messages: ChatMessage[]): Promise<string> {
  const { apiKey, baseURL, model } = readBailianConfig();

  const requestBody: ChatCompletionRequest = {
    model,
    // 只会发送 role 和 content，不透传 id 等前端字段。
    messages: messages.map(({ role, content }) => ({ role, content })),
    stream: false,
    temperature: 0.7,
  };

  const response = await fetch(`${trimTrailingSlash(baseURL)}/chat/completions`, {
    method: "POST",
    headers: {
      // Key 只在「后端 → 百炼」这一段出现，浏览器永远看不到。
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(requestBody),
    signal: AbortSignal.timeout(120_000),
  });

  // …省略错误处理…
  const content = payload?.choices?.[0]?.message?.content?.trim();
  if (!content) {
    throw new Error("阿里百炼没有返回有效内容");
  }
  return content;
}
```

**配置读取（Key 不硬编码）**：

```ts
function readBailianConfig(): BailianConfig {
  const apiKey = process.env.DASHSCOPE_API_KEY?.trim();
  const baseURL = process.env.DASHSCOPE_BASE_URL?.trim() || DEFAULT_BASE_URL;
  const model = process.env.DASHSCOPE_MODEL?.trim() || "glm-5.1";

  if (!apiKey) {
    throw new Error("未配置阿里百炼DASHSCOPE_API_KEY");
  }

  return { apiKey, baseURL, model };
}
```

> **与原报告的差异（可作为对照说明）**：报告参考实现使用 `openai` SDK：
> `new OpenAI({ apiKey, baseURL, timeout })` +
> `client.chat.completions.create({ model, messages, stream, temperature })`，
> 再从 `completion.choices[0]?.message.content` 取正文。
> 本工程不装依赖，改为 `fetch` POST `<baseURL>/chat/completions`，
> **报文、鉴权头、响应取值路径完全一致**，因此装上 SDK 后可等价替换，前两者只差一层封装。

### （2）统一入口（`apps/server/src/services/llm.ts`）

```ts
export async function chatWithConfiguredModel(messages: ChatMessage[]): Promise<string> {
  const provider = (process.env.LLM_PROVIDER ?? "bailian").trim().toLowerCase();

  if (provider === "bailian") {
    return chatWithBailian(messages);
  }

  // 本实验不接入本地 Ollama；如需本地模型，在这个分支补 chatWithOllama(messages) 即可，
  // 上层路由无需改动。
  throw new Error("LLM_PROVIDER只能填写bailian");
}
```

路由只调用这个入口，**不导入任何厂商模块、不判断厂商**：

```ts
const assistantContent = await chatWithConfiguredModel(messages);
```

### （3）路由：运行时校验 + 包装 `ChatResponse`（`apps/server/src/index.ts`）

```ts
app.post("/api/chat", async (request, response) => {
  // TypeScript 不能验证外部 JSON，所以仍需做运行时检查。
  const requestBody = request.body as Partial<ChatRequest> | undefined;
  const messages = Array.isArray(requestBody?.messages) ? requestBody.messages : [];
  const latestMessage = messages.at(-1);

  const userQuestion =
    latestMessage?.role === "user" && typeof latestMessage.content === "string"
      ? latestMessage.content.trim()
      : "";

  if (!userQuestion) {
    response.status(400).json({
      code: 1,
      message: "消息不能为空",
      data: createAssistantMessage("请输入问题后再发送。"),
    });
    return;
  }

  try {
    const assistantContent = await chatWithConfiguredModel(messages);

    response.json({
      code: 0,
      message: "ok",
      data: createAssistantMessage(assistantContent),
    });
  } catch (error: unknown) {
    const errorMessage = error instanceof Error ? error.message : "大模型服务异常";

    // 502 表示 Express 正常，但它调用的上游大模型服务失败。
    response.status(502).json({
      code: 1,
      message: errorMessage,
      data: createAssistantMessage(errorMessage),
    });
  }
});
```

`import "dotenv/config"` 放在文件第一行，确保读 `.env` 早于任何 `process.env` 访问。

## 四、完整调用链与 API Key 安全边界

```text
Vue App.vue
  → Pinia Store（stores/chat.ts）
  → apps/web/src/api/chat.ts
  → POST /api/chat
  → Express apps/server/src/index.ts（运行时校验）
  → services/llm.ts（统一入口，按 LLM_PROVIDER 选择）
  → bailian: 在线 /chat/completions（★ 此处由后端加入 Bearer API Key）
  → Express 封装 ChatResponse
  → Pinia Store → Vue 页面
```

**安全边界位于 Express 后端**：浏览器只知道 `/api/chat`，请求体里只有 `messages`；
`DASHSCOPE_API_KEY` 只存在于后端进程内存与 `.env` 中，并且只出现在后端向百炼发出的
`Authorization: Bearer <key>` 请求头里。

**为什么切换后前端无需修改**：前端始终使用相同的 `ChatRequest`、`ChatResponse` 和 `/api/chat`。
供应商选择、请求格式差异和错误文案转换全部封装在后端 `services` 层，因此改 `LLM_PROVIDER`
后只需重启后端。

## 五、错误处理表（含实测结果）

| 测试情形 | 参考实际结果（实测） | 处理建议 |
| --- | --- | --- |
| 在线 API Key 缺失 | Express 返回 **HTTP 502**，`message` = `未配置阿里百炼DASHSCOPE_API_KEY` | 在后端 `.env` 中补充 Key 并重启 |
| 在线 Key 无效或无权限 | SDK/fetch 抛鉴权错误，后端包装为 `阿里百炼调用失败：HTTP 401/403 …` | 核对 Key、地域、Base URL 和权限 |
| 在线请求频率过高 429 | 上游非 2xx，业务代码统一转为 **HTTP 502** 返回前端 | 尊重 `Retry-After`，仅做有限次数退避重试 |
| 模型服务超时或 5xx | 上游失败，Express 统一返回 **HTTP 502** | 记录原因；仅对临时故障有限重试 |
| `LLM_PROVIDER` 填错 | HTTP 502，`message` = `LLM_PROVIDER只能填写bailian` | 改回 `bailian` 后重启 |
| 消息为空 / 无 user 消息 | HTTP 400，`message` = `消息不能为空` | 修正前端输入 |
| 上游返回空内容 | HTTP 502，`message` = `阿里百炼没有返回有效内容` | 检查模型名与配额 |
| 调用超时（120 秒） | HTTP 502，`message` = `阿里百炼调用超时，请稍后重试` | 稍后重试或换更小模型 |

**「以缺少在线 API Key 为例」的完整验证步骤**：把 `DASHSCOPE_API_KEY` 留空、`LLM_PROVIDER=bailian`，
重启后发送消息 → 页面提示 `未配置阿里百炼DASHSCOPE_API_KEY`，Network 中 `/api/chat` 返回 502；
随后在 `.env` 填入有效 Key、重启服务并再次发送同一问题 → 页面获得正常回答。截图不得包含真实 Key。

## 六、为什么 API Key 只能保存在后端

前端 JavaScript 会下载到用户设备，浏览器开发者工具能够查看源码、请求头和运行时数据，
因此写在前端的 Key 必然可以被提取并滥用。后端环境变量不会发送给浏览器，后端还能集中实施
权限、限流、审计和密钥轮换，所以 Key 只能保存在后端。

本工程的对应措施：

1. Key 只从 `process.env.DASHSCOPE_API_KEY` 读取，代码中没有任何硬编码；
2. `/api/chat` 的响应体只包含 `code` / `message` / `data`，不含 Key；
3. 错误文案经过包装，不透传上游原始报文，也不包含 Key；
4. `.gitignore` 忽略 `.env` 与 `.env.*`，只提交 `.env.example`；
5. 前端源码与构建产物中不出现 `DASHSCOPE_API_KEY`。
